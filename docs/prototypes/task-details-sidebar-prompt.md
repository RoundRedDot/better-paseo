请为 Paseo 的插件 Better Paseo 的「任务泳道看板」设计**桌面端右侧详情侧边栏**及其交互，替换现在卡片悬停 450ms 弹出的详情浮层。产出一份可直接查看、可精确移植的静态 HTML/CSS 设计稿。项目名称设为「Better Paseo · 看板详情侧边栏」。

背景：看板有四条泳道（待输入 / 运行中 / 待查看 / 已完成），每张卡片是一个 coding agent 会话。桌面端现在把鼠标停在卡片上 450ms，会在卡片旁边弹出一个详情浮层；浮层遮住相邻的列，鼠标在卡片之间移动时一直开开关关，很打扰。用户希望去掉悬停浮层，改成像 Linear 那样在看板右侧放一个常驻侧边栏显示详情，侧边栏可以用右上角的按钮开关。

Linear 的参考（用户截图，这里用文字描述）：看板视图右上角有三个 28px 的圆角方形图标按钮（筛选、显示选项、侧边栏开关），侧边栏开关是 panel-right 图标，打开时按钮有一块浅灰底色作为按下态。侧边栏宽约 380px，和看板在同一层，不是浮层；打开后看板变窄，最右一列被裁到侧边栏左缘。侧边栏内容自上而下是几块 surface1 底、圆角 8 的分组卡片，彼此留 8px 间距：第一块是视图标题卡（图标 + 标题 16/600 + 右侧收藏星标和 ⋯ 菜单，下面一行描述 muted）；第二块是属性 key/value（Visibility、Owner，标签列 muted、宽约 140）；第三块是分段切换（Assignees / Labels / Projects，选中项有底色），下面是分组计数列表，每行头像 + 名字 + 右对齐数量，行高约 34。整体很安静：没有阴影，层次只靠底色、间距和 hairline。

需要你设计并说明的交互：
1. 侧边栏显示哪张卡片。我的倾向是：鼠标在卡片上停留约 150ms 就切到这张卡（比 450ms 快，因为不遮挡任何东西）；J/K/H/L 键盘焦点也会切换；鼠标离开卡片时保留最后一张，不清空，这样鼠标能移进侧边栏去点按钮。被显示的卡片在看板上需要一个克制的「当前」标记，和键盘焦点光环、悬停底色都要区分开。另外请考虑要不要「钉住」（例如单击卡片空白处钉住，之后悬停其它卡片不再切换），以及钉住和未钉住怎么区分。现在单击卡片和按回车都会打开 agent 的 tab，请决定是否保留，并给出理由。
2. 没有当前卡片时的空状态：参考 Linear，显示看板概览，例如「107 个任务」、各泳道数量，以及按 Agent / 项目 / 标签分组的计数列表（分段切换），点一行就把它作为筛选条件。也可以给更好的方案。
3. 开关按钮：放在顶栏最右边（搜索框右侧）或筛选栏最右边，选一处并说明理由。用 lucide 的 panel-right 图标，28px 方形，按下态有底色。给一个快捷键（和现有的 J K H L ↵ / 不冲突），并在顶栏的快捷键提示里显示。开关状态要持久化。
4. 布局：侧边栏和看板同一层，打开后泳道变窄（现在的规则是各列平分宽度，每列最窄 300，放不下时横向滚动）。请给出侧边栏宽度（固定还是可拖拽，最小 / 最大值）、和看板之间的分隔方式（hairline，或参考 Linear 的分组卡片加 8px 间距），以及头部是否和顶栏对齐。窗口窄到放不下「侧边栏 + 两列」时怎么办（例如自动改成覆盖在看板上的抽屉，或自动收起），给出阈值。
5. 侧边栏内部滚动：头部和动作区固定、中间滚动，或者整栏滚动、动作区吸底。选一种并说明理由。
6. 状态变化：显示中的卡片换泳道（运行中 → 待查看）、被归档或删除、被筛选掉时，侧边栏分别怎么表现。
7. 在侧边栏里点父任务或子任务：看板滚动到那张卡并高亮，侧边栏切到它；给出「返回」的方式（例如头部左上角的返回箭头）。
8. 开合动画：时长、缓动，泳道宽度怎么过渡。不能逐帧重排所有卡片导致卡顿，可以接受泳道直接跳到新宽度、只给侧边栏做滑入。
