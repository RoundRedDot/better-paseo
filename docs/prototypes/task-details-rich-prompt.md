请重新设计 Paseo 插件 Better Paseo「任务泳道看板」的**卡片详情**：桌面端的右侧详情侧边栏，以及手机 / 平板上的详情 sheet。以 Linear 的设计风格为基础，加入丰富的图表、图标和标签，同时优化桌面端和移动端的 UI 与交互。产出一份可直接查看、可精确移植的静态 HTML/CSS 设计稿。项目名称设为「Better Paseo · 卡片详情 v2」。

## 背景

看板有四条泳道（待输入 / 运行中 / 待查看 / 已完成），每张卡片是一个 coding agent 会话。桌面端在看板右侧有一个常驻侧边栏（宽 340–520，可拖拽，默认约 380）：最上面是统计卡（「99 个任务」+ 四个泳道计数），下面是选中卡片的详情。手机上点卡片会弹出详情 sheet（半屏 / 全屏两档），内容和桌面一样。

附件：

  - 头部：状态行、标题、「模型 · 思考等级 · 模式」、「打开 tab」按钮，右上角是钉住和关闭。

现在的问题：信息全是「标签 + 文字值」的平铺行，读起来像表格，没有重点；数字都是单独的文字，看不出比例和趋势；没有任何可视化；状态、模式、分支状态这些也只是灰色文字。用户希望在保持 Linear 精致、克制的前提下，让详情更有信息层次、更好扫读。

## 可用数据（只能用这些；想用新数据请单独标成「需新增数据」，不要混进主稿）

每张卡片有：
- 状态：needs_input / running / unread（待查看）/ failed / done，可能是「手动停止」；所在泳道。
- 标题；provider（Claude、Codex、Gemini 等，有品牌标识）、模型名（Opus 5.5）、思考等级（High）、权限模式（Bypass / Plan / Default 等，有对应图标）。
- 位置：项目名、workspace 名、workspace 类型（本地 checkout / worktree / 普通目录）、分支、git 状态（ahead 数、behind 数、是否有未提交改动；或「非 git 目录」）、工作目录完整路径、关联 PR（编号、标题、URL）。
- 标签：0–n 个，每个有名字和颜色（可能没有颜色）。
- 时间：createdAt、updatedAt、lastUserMessageAt（最后一条用户消息）、turnStartedAt（运行中这一轮的开始时间）、attentionAt（开始等待输入的时间）、lastTurnMs（上一轮耗时）。
- 上下文：已用 token、上限 token（例如 225k / 1.00M）。
- 用量：input token、缓存 input token、output token、累计费用 USD（任一项都可能缺失）。
- 失败时的错误原文；待输入时的权限请求（类型 tool / plan / question / mode，标题，一行命令或文件摘要，按钮列表：允许 / 拒绝 / 回答，以及还有几个请求）。
- 父任务（标题，可能已归档）；直接子任务列表（每个有标题和状态）。
- 是否已有客户端打开了它的 tab；能否停止。

图表请基于这些数据来设计。例如：
- 上下文：环形或分段的用量仪表，阈值配色（< 75% muted，75–89% warning，≥ 90% danger）。
- token 构成：缓存 / 新输入 / 输出的堆叠条，并带图例。
- 时间线：创建 → 最后一条消息 → 本轮开始 → 更新，画成一条带刻度的小时间轴，标出各段耗时。
- 子任务：按状态分段的进度条，加计数。
- git：ahead / behind 的小徽标，未提交改动用状态点。
可以有更好的方案，但每个图都要说明它用的是哪几个字段。

## 设计方向

1. **Linear 风格**：层级靠字重、灰度和间距；hairline 分隔；图标统一用 lucide 16px、描边 1.5；标签用 Linear 式胶囊（色点 + 名字，hairline 描边，高 22，圆角 999）。不用渐变、插画、emoji，不用大面积饱和色块；状态色只用于小号文字、圆点、细条和图表的填充。
2. **信息层次**：把最需要先看的东西放在最前面。例如运行中看本轮计时和上下文，待输入看权限请求，失败看错误，已完成看耗时和费用。可以按状态调整区块的顺序或折叠方式，并说明规则。
3. **区块**：可以引入 Linear 式可折叠区块标题（chevron），或者「概览 / 用量 / 活动」这样的胶囊页签（Linear 项目页的 Overview / Activity 胶囊：高 28、圆角 999、前置 14px 图标；选中是灰底加 hairline，未选中是白底加 0.5px 描边和极淡投影）。二选一或组合，说明理由。
4. **图标与标签**：每个属性行有前置图标；状态、模式、workspace 类型、分支同步状态、PR 状态都可以做成小标签或徽标，但同一行里最多一个彩色元素。
5. **交互（桌面）**：属性的复制（点击复制并在行尾出对勾）、hover 显示的次级动作（外链、定位到看板）、图表的 hover tooltip（显示精确数值）、区块折叠记忆、键盘可达（Tab 顺序、焦点环）。侧边栏宽度从 340 变到 520 时，图表和两列布局怎么自适应。
6. **交互（手机 / 平板）**：
   - sheet 两档高度：半屏时只露出头部和最关键的图表，全屏时展示全部。
   - 「打开 tab」是吸底主按钮（高 48，让出 34 的安全区）；运行中旁边是「停止」，待输入时是允许 / 拒绝 / 回答。
   - 左右滑切换同泳道的上一张 / 下一张。
   - 图表在触屏上没有 hover，改成点按显示数值。
   - 行高 44，图标 18，字号 15。
   平板（iPad 横屏内嵌、竖屏浮动）沿用桌面布局和触屏尺寸。

## 实现约束

- 最终在 React Native（含 Web）里用 flexbox 实现。**插件沙箱里没有 react-native-svg**，所有图表都只能用 View 拼出来：矩形条、分段条、圆角、边框；环形用「边框着色的圆 + 裁剪的两个半环」实现，只能画单一颜色的连续弧，不能画多段彩色环。不要用 SVG、canvas、clip-path、conic-gradient；如果设计稿里为了展示用了 SVG，请在规格里写清楚它对应的 View 拼法。
- 宿主主题任意，插件只能拿到这些颜色 token：surface0、surface1、surface2、border、foreground、foregroundMuted、accent、success、warning、danger。新颜色请写成 token 推导公式（例如 mix(accent 13%, surface0)），并给出浅 / 深两套参考值。
  - 浅色：surface0 #ffffff、surface1 #f6f6f7、surface2 #ededef、border #e2e2e6、foreground #18181b、foregroundMuted #62626b、accent #2563eb、success #1f8a5b、warning #a36a00、danger #d92d20。
  - 深色：surface0 #0f0f11、surface1 #17171a、surface2 #1f1f23、border #2a2a30、foreground #f2f3f5、foregroundMuted #a3a6ad、accent #7aa2f7、success #4cb782、warning #e0a84a、danger #f2555a。
  - 状态点颜色：运行中 #268ae0，待输入 #b37824，待查看 #299f51，失败 #f12e2f；深色分别是 #5caaf6、#db932e、#35c264、#f7796d。
- 详情卡外框：浅色 surface0、深色 surface2，hairline 边框，圆角 12，极淡投影；文字距卡片边 12。
- 字号下限 11px，数字一律 tabular-nums，不新增字体。
- 数据缺失时（没有用量、没有上下文、非 git 目录、没有子任务）每个图表和区块怎么退化，要画出来。
