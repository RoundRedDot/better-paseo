请为 Paseo 的插件 Better Paseo 重新设计**任务详情里的「子任务」区块**。现在这块排版太粗糙，需要一版精致、可精确移植的静态 HTML/CSS 设计稿。项目名称设为「Better Paseo · 详情子任务」。

## 背景：任务详情

任务看板的每张卡片是一个 coding agent 会话。点开卡片后看到它的详情，容器有三种：

- 桌面侧边栏：宽 340–520，默认 380，鼠标操作，正文 13；
- 平板 sheet：分两栏，子任务放在左栏标题下面，右栏是其余区块；
- 手机 sheet：宽 390，触屏操作，正文 14，行高 44。

详情是一张卡片，从上到下依次是：

1. 头部：状态行、标题、模型 chip、「打开 tab」和「停止」、本轮计时和上下文环；
2. 几个可折叠区块：子任务、属性、用量、活动。

区块标题行的样式：

- 高度：桌面 32，触屏 44；
- 左边是标题（12/500 muted，触屏 13）加 chevron；
- 右边是摘要；
- 区块之间用 hairline 分隔，左右各缩进 12。

附件 current-details-touch.png 是现在触屏下的详情。红框就是这次要重做的子任务区块，里面有 4 个子 agent，全部已完成。

## 现在的子任务区块

- 标题行：左边「子任务 ⌄」，右边「4 / 4 完成」加一个 14 的进度环；全部完成时进度环换成绿色 circle-check。
- 每个子任务一行：
  - 左边是 14 的 provider 标记（灰色），右下角叠状态：运行中是 12 的蓝环，待输入是琥珀色空心环，待查看是 8 的绿点，失败是红点，已完成不画；
  - 右边第一行是标题，最多两行；
  - 第二行是 facts，12 muted，例如「Opus 5.5 · High · Bypass · 288k / 1m tokens (29%)」。
- 点一行就在详情里跳到这个子任务，详情顶部会出现「返回」。
- 子任务超过 10 个时，后面的收起，末尾放一行「显示全部 N 个」。

## 看得出的问题

1. 信息重复，有用的反而埋掉了。
   - 4 行的「Opus 5.5 · High · Bypass」完全一样，是纯噪音。
   - 真正区分各行的信息没有显示：状态、跑了多久、什么时候结束、上下文用了多少。
2. 状态看不出来。
   - 已完成的行没有任何标记，「完成」只出现在标题行的计数里。
   - 运行中、待输入的行也只有角上一个很小的点。
3. 对齐松散。
   - 标记在两行文字之间垂直居中，没有和标题首行对齐。
   - 行与行之间没有节奏。
   - 区块底部的 hairline 和下一个区块「属性」的标题挤在一起。
4. token 写成长文本「288k / 1m tokens (29%)」，不好扫读。
5. 和卡片不一致。
   - 看板卡片展开后的子任务行，结尾已经有起止时间和计时：运行中是「14:41 · 14m 14s」，结束后是「上一轮 3m 2s · 12 分钟前」。
   - 详情里反而没有这些。
6. 标题常带前缀，例如「[Handoff] …」或 Linear 编号「RRD-11366 …」。可以考虑把这类前缀弱化或单独排版，由你决定。

## 每个子任务能拿到的数据

- id、标题；
- 状态：running / needs_input / unread（完成未读）/ failed / done；
- provider（claude、codex、grok…），以及模型、思考强度、权限模式的显示名；
- 上下文：已用、窗口大小、百分比，可能缺失；
- 所在泳道，以及时间：创建时间、本轮开始、上一轮结束、上一轮耗时、更新时间。

父任务自己的模型、思考强度、权限模式也知道。所以子任务的这几项可以只在和父任务不同时才显示，也可以干脆不显示，由你决定并说明理由。

## 需要你设计并说明的

1. **行的结构。** 标记、标题、次要信息怎么排，各占几行。
   - 状态怎么表达：沿用角标，还是放在行尾，或者别的方式。
   - 时间和计时放在哪里；运行中的计时会每秒跳动，要用 tabular 数字。
   - 上下文怎么表达：数字、细条，还是只在超过 75% 时提示。
2. **排序和分组。** 混合状态时要不要排序或分组，例如待输入、运行中、失败、待查看、已完成依次排列。
   - 已完成的行要不要整体弱化。
   - 全部完成、全部运行中，各是什么样。
3. **标题行的摘要。**
   - 「4 / 4 完成」加进度环是否保留。
   - 混合状态时要不要拆成按状态的计数，例如「1 待输入 · 2 运行中 · 3 完成」。
4. **交互状态。**
   - 悬停：桌面整行变底色，行尾出现 ↗ 打开 tab。
   - 按下、键盘焦点、跳转。
   - 超过 10 个时的折叠行。
   - 待输入的子任务要不要在这里直接给「去处理」入口。
5. **三种宽度。** 桌面侧边栏 340 / 380 / 520、平板左栏、手机 390，各给出适配规则：
   - 长标题怎么折行；
   - 窄宽时次要信息怎么取舍。
6. **和区块分隔的间距。** 标题行、首行、末行、hairline、下一个区块之间的距离，给出确切数值。

## 约束

- 最终用 React Native（含 Web）的 flexbox 实现，宿主主题任意。
- 插件只能拿到这些颜色 token：surface0、surface1、surface2、border、foreground、foregroundMuted、accent、success、warning、danger。新颜色请写成 token 推导公式，并给出浅、深两套参考值。
  - 浅色：surface0 #ffffff、surface1 #f6f6f7、surface2 #ededef、border #e2e2e6、foreground #18181b、foregroundMuted #62626b、accent #2563eb、success #1f8a5b、warning #a36a00、danger #d92d20。
  - 深色：surface0 #0f0f11、surface1 #17171a、surface2 #1f1f23、border #2a2a30、foreground #f2f3f5、foregroundMuted #a3a6ad、accent #7aa2f7、success #4cb782、warning #e0a84a、danger #f2555a。
- 详情卡片的底色：浅色 surface0，深色 surface2；1px hairline 边框，圆角 12。
- 图标只用 lucide，线宽 1.5（宿主就是这样画的）。
- provider 标记就是各家的品牌 logo，灰色单色，14px。
- 字号不小于 11，不新增字体，不用渐变，也不要彩色整块底色。
- 整体要安静：层次只靠字重、灰度、间距和 hairline。
