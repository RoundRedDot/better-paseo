请为 Paseo 设计一个「Tasks」泳道看板的交互原型，产出一份可直接查看、可精确移植的静态 HTML/CSS 设计稿（关键交互用少量 JS 演示即可）。项目名称设为「Paseo Tasks · 泳道看板」。

## 背景

Paseo 是一个管理 coding agent（Claude Code、Codex、Cursor、Grok 等）的桌面与移动端 App。一个用户同时在多个 workspace 里跑几十上百个 agent（本机实测 340 个未归档，其中 11 个在运行）。现在的侧边栏按 workspace 组织，看不到全局：哪些在跑、哪些在等我输入、哪些跑完了还没看。

我们要在侧边栏顶部那一组入口里（附件 paseo-sidebar.png 红框：新建工作区、历史、搜索、计划、Agents history）新增一项「Tasks」，点开是一个整页看板，把所有 agent 当作任务，按状态分泳道铺开。

## 风格

- 结构以 Linear 的看板（board layout）为模板：顶部一条紧凑的过滤 / 显示选项栏；下面横向排列的列，每列顶部是「状态图标 + 列名 + 数量」；列内是信息密度高、行距紧凑的卡片；键盘友好；整体安静克制。
- 视觉语言用 Cloudflare 新版官网的简洁线条风格（附件 cloudflare-style.png）：
  - 用 1px 细线而不是色块来划分区域：列与列之间是一根竖向细线，而不是每列一个灰底圆角容器；
  - 虚线作辅助线，网格交点处有小方块角标；
  - 空白区域可以有很淡的点阵底纹；
  - 按钮是描边胶囊，标签是细描边小方角 chip；
  - 色彩极度克制，只有状态才用颜色；不要渐变、不要厚重阴影，只有浮层（菜单、弹出详情）才有轻阴影。
- 两者结合：Linear 的骨架和密度，Cloudflare 的线条和留白。

## 实现约束（必须遵守）

- 最终在 React Native（Web / iOS / Android）里作为 Paseo 插件实现。宿主主题任意，插件只能拿到这些颜色 token：surface0（页面底色）、surface1、surface2、border、foreground、foregroundMuted、accent、accentForeground、statusSuccess、statusWarning、statusDanger。
- 不能写死品牌色。所有派生色写成上述 token 的公式（例如 accent 12% 不透明度，foregroundMuted 与 surface0 按比例混合），并给出浅色、深色两套参考取值。
  - 浅色参考：surface0 #ffffff、surface1 #f6f6f7、surface2 #ececee、border #e2e2e6、foreground #1b1b1f、foregroundMuted #6b6b75、accent #3b6fe0、success #1f8a5b、warning #c98a12、danger #d23c3c。
  - 深色参考：surface0 #18181b、surface1 #1f1f23、surface2 #27272a、border #2e2e33、foreground #ececef、foregroundMuted #9b9ba5、accent #6b9cff、success #3fb97e、warning #e0a53a、danger #ef5b5b。
- 图标只用 Lucide（按名称引用）。agent 品牌标识用 16×16 的圆角位图占位，标出 Claude、Codex、Cursor、Grok 即可。
- 字体跟随宿主界面字体，不新增字体。时长、计数等数字用等宽数字（tabular-nums）。字号不小于 11px。
- 不支持拖拽：泳道由 agent 状态自动决定，卡片不能在列间拖动。

## 泳道与归列规则

四列，从左到右，需要人处理的在最左：

| 列 | 归入条件 | 列内排序 | 状态图标建议 |
| --- | --- | --- | --- |
| 待输入 | 有挂起的权限请求或提问 | 等得最久的在上 | warning 色 |
| 运行中 | 正在执行（含启动中） | 跑得最久的在上 | accent 色，可带细微的进行中动画 |
| 待查看 | 跑完但用户还没看过；或失败 | 最近的在上 | 未读点；失败用 danger |
| 已完成 | 其余（空闲、已关闭） | 最近更新的在上 | foregroundMuted |

已完成列默认只显示最近 24 小时，可切换 7 天 / 全部，每次加载 50 条，底部「加载更多」。

## 卡片内容

每张卡片固定显示：标题（agent 名称，单行截断）、workspace 名、agent 品牌标识 + 模型 + 思考等级（如「Opus 5.5 · High」）。随列变化的部分：

- 待输入：权限请求摘要（如「Bash · npm test」或「Edit · client/state/board.ts」）+「允许」「拒绝」按钮 + 已等待时长。提问类请求（如让用户选择部署环境）只显示问题标题和「去回答」按钮。同一 agent 有多条请求时只显示第一条并标「还有 N 条」。
- 运行中：本轮已运行时长（每秒走动，如「12:30」）、上下文占用细进度条（超过 80% 变 warning、90% 变 danger）、子任务摘要（「子任务 2 · 1 运行中」）、悬停时出现的「停止」按钮。停止需二次确认：点一下变成「确认停止」，3 秒内再点才执行，否则复原。父任务的停止按钮带一个下拉：「仅停止此任务 / 连同子任务一起停止」。
- 待查看：未读点或失败原因（一行 danger 文字，如「exit code 1」）、上一轮耗时（约值，如「约 8m」）、完成于多久前。
- 已完成：上一轮耗时（约值）、完成于多久前。

父子关系：
- 子任务卡片顶部有一行「↳ 父任务标题」，点它在看板上滚动到父卡片并高亮 1 秒，不跳走。
- 父任务卡片底部有子任务摘要，可展开成子任务清单（状态点 + 标题），点任一行跳到该子任务。
- 过滤栏里有「隐藏子任务」开关，打开后子任务只在父卡片的清单里出现。

点卡片主体：跳到该 agent 所在 workspace 的对应 tab（原型里给个点击反馈即可）。按钮区域单独响应，不触发跳转。

悬停卡片（触屏长按）弹出详情浮层：cwd、创建时间、模式（如 Bypass / Plan）、input / output token、费用、上下文 token 数。

## 过滤栏

Workspace 多选、Agent 多选（Claude / Codex / Cursor / Grok）、「只看开着的 tab」、「隐藏子任务」、按标题搜索、已完成时间窗口。已选条件以细描边 chip 显示，可逐个清除。

## 侧边栏入口

在侧边栏现有入口组里加一行「Tasks」（Lucide 看板类图标），右侧显示「运行中 · 待输入」两个计数：都为 0 时不显示；待输入大于 0 时该数字用 warning 色。停在 Tasks 页时该行高亮，与现有选中样式一致。
