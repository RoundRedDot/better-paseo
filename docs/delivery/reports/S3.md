## Findings (path:line — change)

### 1. The file name stays visible
- **Cause.** `PathText` truncated to a fixed 40/72-character budget, while the real slot on a phone is about 23 characters. The row's `numberOfLines` tail ellipsis then cut the file name.
- A second, web-only cause showed up during the fix: the embedded Iosevka subset has no `…` glyph. Each ellipsis falls back to a face about two cells wide (measured 13.3 px against 6.5 px per character), so rows with two ellipses overflowed by a cell.
- `client/paths/truncate-middle.ts` (pure, tested):
  - `fitMiddle(text, budget)`: like `truncateMiddle`, but never over budget. When `…/name` does not fit, it cuts the name in its middle, so the start and the extension both stay (`…/respon…er.ts`), never at its end.
  - `monoAdvance(family)`: 0.5 em for Iosevka, 0.6 for SF Mono/Menlo/monospace, 0.64 for unknown faces.
  - `budgetForWidth(width, fontSize, family)`: characters that fit, less one of slack; null until measured.
  - `ellipsisCells`, `cellWidth`, `fitCells`: fitting counted in character cells, with the ellipsis as two cells for Iosevka and one otherwise.
  - `shownPath(formatted, limit, strict, ellipsis)`: what `PathText` draws. In a measured slot, a secondary root's label (`beautiful-chat/…`) is dropped before the file name is ever shortened.
- `client/ui/path-text.tsx`: new `fit` prop.
  - A stretching slot View is measured with one `onLayout`. State is updated only when the rounded width changes, so there is one extra render of the path per mount and none per chunk.
  - The pressable stays the width of the text, so a tap beside the path still toggles the row.
  - The reserved hover-copy-icon width is subtracted. Fixed-budget behaviour is unchanged when `fit` is off (Markdown and other callers).
- `client/components/tool-callouts.tsx:189, 614, 668`: the header target, the search file rows and the worktree path use `fit`. The worktree branch name moved below the path, so the path sits in a column slot.

### 2. Hover fix moved into `DisclosureHeader`
- `client/ui/disclosure-header.tsx:215`: on web, the hover wrapper is a View with DOM `onMouseEnter`/`onMouseLeave`, which don't bubble and cover the overlay too. Native keeps the hover-only Pressable (iPad pointer, no containment there).
- `actionsActive` prop (`:58`, `:106`): keeps the hover overlay up without the pointer, e.g. while the `⋯` menu is open. The meta stays hidden by opacity, so nothing moves.
- `aria-expanded={expanded}` (`:122`) alongside `accessibilityState={{ expanded }}`.
- `tool-callouts.tsx` no longer has its own hover state, overlay or meta rendering. It passes `actions` plus `actionsActive={menu.open}` and plain meta strings (plus the `MetaPath` node). S4's reasoning header gets the fix too: its 6 headers in the reasoning shot now carry `aria-expanded`.
