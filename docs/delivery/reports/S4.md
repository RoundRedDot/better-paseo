## Findings (path:line — change)

**New: `client/reasoning/**`**
- `segment.ts:187` `createReasoningSegmenter()` / `:256` `segmentReasoning(text, {streaming})` return `{kind:"sections", sections:{title|null, body}[], steps}` or `{kind:"prose", body}`.
  - Sections: at least one standalone `**Title**` line. Otherwise, the shallowest heading level that occurs at least twice.
  - Text before the first title becomes an untitled intro (`title: null`).
  - Everything else is prose: ordered lists, bold inside a sentence, bold in list items, and anything inside fenced code.
  - Incremental: each update scans only newly completed lines. The open last line is re-read every time (the one-line lookback). While streaming, a last line that could still become `**Title**` (for example `**Underst` or `**Title**` with no newline yet) is held back, so no literal asterisks flash in.
  - Section objects that come out identical are reused, so memo can bail out. No `class`, no lookbehind, no `v` flag (D9).
  - `reasoningText()` turns a segmentation back into Markdown for copying.
- `preview.ts:125` `reasoningHeaderText()` produces the four header states from §3.4 item 3:
  - streaming + sections: current section title
  - streaming + prose: last complete sentence (the unfinished tail is ignored, so the preview changes once per sentence)
  - done + sections: `N steps · 12s`
  - done + prose: first sentence `· 12s`
  - Also here: `plainInline`, `firstSentence`, `lastCompleteSentence` (supports CJK full-width punctuation and closing `**`/quotes), `formatDuration`.
- `observed.ts:32` duration record.
  - The first render that sees the thought streaming stores the host timestamp it carries. Every later render pushes the end forward to the newest timestamp.
  - Both ends are host time, so there is no clock skew between device and daemon.
  - A thought first seen complete (history, reload) has no record and shows no duration.
  - Module-level LRU of 2000 entries, so the record survives a remount.
  - Deviation: the brief said "record first-render time". I record the host timestamp at the first render instead of the local clock, to avoid skew. It is still the moment this client first saw the thought.
- `key.ts:18` key = `${agentId}:reasoning:${hashText(first 80 chars)}` (reuses S1's `hashText`). `useReasoningKey` (`:38`) handles texts shorter than 80 characters, whose hash changes per chunk: inside the mounted card it carries the reader's choice and the duration record over to each new key.
- `paragraphs.ts:71` `splitBodyRuns`: a plain paragraph over 600 characters becomes its own run. Fences are never split on their blank lines. Lists, quotes, tables, headings and code are never clamped. All other blocks stay together in one Markdown run, so loose lists stay whole.
- `fade-in.tsx:12` expand fade: opacity over 120 ms, native driver on iOS/Android, 0 ms under reduced motion. This could move to `client/ui` later (see Remaining).
