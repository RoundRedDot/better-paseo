# Better Paseo 视频脚本与制作 Prompt · V11 重点与节奏重排

更新日期：2026-10-17。本轮**只更新脚本，不制作或改写视频**。当前已交付 V10：166 秒全功能试剪；用户反馈为“功能点都讲到了，但节奏慢、重点不突出”，要求将小功能合并讲述，突出产品的差异化优化。V11 尚无成片或锁定时间线。

本轮改为“紧凑工作现场 → 持续生成的渲染优化与实测 → 工作流复用”的主线。核心能力获得连续演示和明确结论，小功能在同一章节内接续，减少重复标题、重新摆镜头和空白停顿。**136 秒是当前脚本工作预算，建议试剪范围 130–140 秒，不是已确认的最终成片时长。** 旧 150–170 秒预算已完成为 V10，不再作为 V11 的时长下限。

“独有优化”在本脚本中指 Better Paseo 值得突出的实现与体验特点；没有竞品排他证据时，不写“唯一”“全网独有”。性能继续使用 `b9dfae6` 的已发布 Web 数据，不重算或替换；V10 新 UI 固定 `2c0d842`，旧 V5 支持副本为 `18ad7c2`，来源不可混称。

## 重排验收

- 静音看前 25 秒，能复述“工具收成一行、打开预览仍跟随新输出”；前 51 秒能辨认渲染优化与限定内的数据依据。
- 每个大章只有一个价值主张；章内连续动作不反复回到相同空白全景、重复品牌或再次解释相同的复制入口。3–7 秒的辅助子镜头不等于新的主标题页。
- 核心变化、操作入口和结果可读；真实等待与完整结果不得因提速而消失。若试剪超时，先收掉重复导航、冗余反馈和解释文案，再回调可选分支。
- 已有四性能场景、两页11项、手机20秒、设置18秒、完整详情/问答停顿和可读CTA均能在章节表定位；按取证细则验收，不能只在背景露出即记为已讲到。
- 首先审视重点是否突出、转场是否必要，再核对总长；不能只因比166秒短就认定节奏合格。

## 功能取证细则（按章内子镜头验收，不是独立章节）

以下保留操作语义、默认值和来源约束。这里列出的说明短句用于同一大章内的字幕，**不再据此为每个小功能建立独立标题页**。

### 桌面：收起复杂度，保留运行过程

1. 工具调用收成一行：同一轮里清楚展示 Read、Edit、Shell、MCP 等不同摘要、路径与 +/−；点击展开再折叠。展开状态跨完成／历史返回的保持需要实际录制，不能仅凭两张截图证明。
2. 悬停即看：鼠标移到折叠工具行，保留默认 1.0 秒等待，再打开预览。不要把弹窗出现前就切走。
3. 弹窗里，继续看输出：弹窗已经打开后继续产生可识别的新行，镜头连续展示内容增长与正常尾部跟随，再保留停止后的结果。不能只滚动静态日志冒充流式输出。
4. 双击标题，就能放大：在工具栏标题或空白处真实双击一次，展示从浮窗到最大化窗口的响应；阅读期间不再双击。关闭使用关闭按钮，或单独演示第二次双击会关闭整个预览。拖动、边缘缩放另拍，不把点击“最大化预览”按钮冒充双击。
5. 拖动与调整大小：保留真实拖动、边缘缩放及结果；不要用后期缩放整张录屏代替窗口操作。

预览支持换行、行号和奇偶行底色；在对应操作中清楚露出按钮及效果。行号提前开启，持续标“行号提前开启 · 默认关闭”。
移除旧录制脚本里为演示主动发送的反向滚轮操作；逐帧检查内容增长期间和相邻切点不发生非预期回退。若另拍“上翻阅读”，必须明确这是用户操作，离开末尾后不再自动跟随，回到末尾后才继续跟随。

### 用户问答：回答过的内容，随时回看

在“把结果接回工作流”章内展示受支持提问调用的结构化记录：问题、选项、已选答案与并入“回答”区域的已有补充文字（没有独立补充栏）；切换下一题后留出阅读时间，展示多题分页及状态。原始数据切换可作为补充细节。
章内说明文案（不单独起大标题／章节）：“问题和回答，都有记录。”
这是问答记录回显，回答由 Paseo 处理；不在只读卡片里表演勾选或提交，不伪造从等待到完成的业务结果。演示数据须标为离线示例；若拍状态变化，记录实际输入数据更新。

### 实时待办：进度留在眼前

点击待办标题栏的“在窗口中打开任务”按钮打开持久浮窗，继续操作时间线时保持打开；不使用移出指针就关闭的标题悬停预览代替。任务源数据更新时展示最新状态和进度环；结束时展示完成标记。状态图标的点击仅修改本地展示，不能用于表演真实任务进度更新。
阻塞项及原因、长标题换行可作补充。仅有主题截图里的静态列表不算演示实时浮窗，不把本地展示状态包装成写回 agent 成功。
章内说明文案（不单独起大标题／章节）：“进度，随时看。”

### 选中、复制与复用

行号拖选整行 → Copy：复制源码保留内部缩进与换行，不包含显示行号；用真实剪贴板读回核对。V10 已发现选区最前面的空格会被 trim，主片采用从无前导缩进的函数声明开始的范围，不泛称选区边缘空白完整保留；失败证据仍保留。
局部文字／代码选区 → Add to chat → 输入框中出现引用，代码选区保持代码块格式。内容复用子段固定验收“引用进入真实输入框”，先确认支持该能力且输入框可见，不自动发送。若没有可用宿主草稿证据，该镜头仍未完成，不能以复制成功替代或直接开拍；无输入框时实际会提示“已复制到剪贴板”。不能用离线假输入框补造成功。
表格子段固定“复制为 Markdown → 剪贴板读回”一个结果，保留既有移动镜头。复制为图片、复制选中分别进入补充清单，不强塞进同一镜头；图片复制需网页运行环境支持 ClipboardItem，录前检查实际菜单能力。每个实际采用的分支都保留真实结果。
章内说明文案（不单独起大标题／章节）：“选中，就能接着用。”

### Markdown：预览和原文，按需切换

点击代码块上的“在窗口中打开 Markdown”，一次打开并最大化预览，再在同一窗口切换渲染视图和原始文本、复制源码。入口仅适用于未标语言或 md、markdown、text、txt、plaintext 的代码块，不套用到任意语言代码块。固定同一份内容，便于理解切换。
文档／紧凑／终端三种回复样式、读图缩略图与全屏查看器、查找和路径操作列入补充镜头清单，不用过快拼贴代替完整演示。

### 运行结束：时间和 token，都能回看

在工作流章内保留完整的“完成 → 回复信息栏 → 详情 → 阅读”镜头，不能只在全景角落露出数字。
先展示本轮结束后的最终回复及其下方信息栏，清楚可见沙漏图标及紧凑时间显示的实际运行耗时；桌面鼠标停在模型名称上，保留真实约 400 毫秒延迟后打开“轮次详情”。手机入口为长按回复底部信息栏，若采用手机镜头则单独录制，不把桌面点击套用到手机。
详情稳定保留至少 3 秒，按中文界面原文呈现：Agent、模型名称、思考强度、开始时间、结束时间、耗时、输入、缓存、输出。后三项的说明文案可解释为输入 token、缓存输入 token、输出 token，不能在后期重绘或改写 UI 标签。必要时同帧局部放大，保证标签和数值可读。
章内说明文案（不单独起大标题／章节）：“结束之后，时间与用量一目了然。”副标题：“本轮运行时间 · 输入 / 缓存 / 输出 token”。
