# Better Paseo 视频脚本生成 Prompt

更新日期：2026-10-17。默认用于 58 秒、16:9、中文旁白的开发者产品宣传片，成片硬上限 60 秒，重点展示连续交互动画。

实测源码固定为 `b9dfae6`；文档与部署版本 `c27cfaa` 没有改变插件运行时代码。后续更新数字时，以新一轮完整报告重新核对，不将不同批次的数据拼接使用。

## 可直接复制的 Prompt

```text
你是一名熟悉开发者工具的产品视频编导。请为 Better Paseo 编写一支 58 秒宣传片的完整脚本，包含时间码、画面、逐字中文旁白、屏幕文字、字幕和素材对应关系。

【目标与受众】
面向使用 Paseo、Claude Code、Codex、Oh My Pi 等工具的开发者。
让观众理解：Better Paseo 是重绘 Paseo 聊天时间线的插件，让工具调用、思考、回复和待办更容易阅读、预览与复制。
它不是独立的 AI 编程服务，也不改变模型的推理能力或代码质量。
核心表达：“工具调用收成一行，把注意力留给工作。”

【形式与风格】
58 秒，16:9，1920×1080，中文旁白和字幕，保留产品名、工具名和命令的英文写法。
以“高效、直观、优雅、现代”为明确视觉目标：界面是主角，少量旁白解释价值，操作结果直接说明功能。
浅色为主，用一次同构画面切换展示深色；延续产品字体、圆角与强调色，背景干净，文字层级清楚。每屏只设一个视觉焦点，一条短标题；除字幕和数据必要说明外，不堆叠文案。
鼠标沿清楚、短而自然的路径移动；点击提示仅一圈轻量标记。完成关键操作后停留约 0.5–0.8 秒，让结果可辨。局部放大保留控件与内容的上下文，避免频繁跳焦。
界面响应使用真实录屏速度，保留 hover 等待与成功反馈；通过删除无关操作和空白缩短时长。剪辑优先硬切、位置匹配与一次主题匹配切换，必要的镜头转场约 160–240 ms，计入总时长。
旁白目标 110–140 个汉字，语速自然；字幕最多两行，单条屏幕标题尽量不超过 10 个汉字。音乐使用轻量、清晰的节拍，给操作和阅读留出空隙。
以提供的实际截图或录屏为界面依据。可以裁切、推近、添加说明和转场，不生成不存在的按钮、能力、成功状态或性能读数。
手机外框和离线 showcase 截图须标为“界面示意”；静态图片的推近、平移不冒充真实交互录屏。
没有真实录屏的功能镜头，用静态截图加操作说明表达，不伪造点击后状态。
音乐低于人声，避免科幻霓虹、粒子、夸张音效和密集术语。

【可展示的功能】
1. 一个工具调用对应一行摘要，默认折叠。用 Shell、Read、Edit diff 展示不同工具的识别与摘要；需要细节时再展开。
2. 桌面悬停、手机长按，可预览折叠行的内容；预览正文可滚动，桌面面板可拖动、调整大小和最大化。
   开启“显示行号”后，可从行号栏选择整行文本；也可在支持选择的正文中拖选局部文本。
3. Markdown 回复逐块呈现；展示标题、列表、代码高亮和表格。桌面表格可复制为 Markdown；不要把“复制为图片”演示成手机通用能力。
4. 待办清单呈现实际状态；图片支持全屏查看、缩放与平移。
5. 浅色、深色跟随宿主主题，设置有实时预览及中英文界面。
不展示自动批准权限、替用户回答问题、重启或取消 hub 任务，也不把多个调用合并成一个调用行。依赖未发布宿主能力的功能不作为通用卖点。

【交互动画与录屏规范】
视频以“光标或手势 → 界面响应 → 阅读停顿 → 下一步操作”为主线，不做只有截图推近的功能轮播。
每个动作都要交代起点和结果：光标移到哪个控件、何时按下或松开、选区如何扩大、反馈出现在哪里。镜头切换前保留可读的结果状态。
- 鼠标 hover：光标移入折叠工具行，按录制设置等待后出现预览，再移入预览正文。默认延迟为 1 秒；若录制时修改设置，应注明实际值，不伪装为默认瞬时弹出。
- 预览浮窗：在正文内滚轮滚动，工具行和面板标题保持可辨；从标题栏空白处拖动，再拖边缘调整大小，最后点击实际最大化按钮。最大化后的关闭按钮是关闭预览，不编造“还原”按钮。
- 滚动与换行：展示纵向阅读；横向滚动仅在关闭自动换行、内容超宽时演示。只用实际滚动响应，不通过剪辑制造“零卡顿”或速度对比。
- 行号拖选：录制前开启“显示行号”（默认关闭）；短片以“已开启行号”标注交代前提，设置页操作不占主片时长。随后进入 Read 预览。桌面从某一行号按下并拖到另一行号，呈现连续整行选区；复制结果保留源码缩进和换行，不包含显示行号。不要演示未实现的 Shift+click 或凭空出现的选区手柄。
- 局部文本选择：在支持选区工具栏的 Web 工具正文中，用鼠标拖选一段文字，停顿展示 Copy / Add to chat 浮条；点击后展示实际成功勾选反馈。演示 Add to chat 时必须有同一聊天的可见输入框，并拍到引用写入草稿，不表现为自动发送。另选一段后滚动，拍到浮条收起、文字选区保留。
- 表格选区可作备选镜头：桌面双击单元格选择整格内容，再展示实际复制菜单。不要把整格选择画成只选中了一个单词。
- 触屏手势：普通滑动用于滚动；长按折叠行用于打开预览；开启行号后，在行号栏长按约 400 ms 再拖动用于选择整行。手机行号选区使用插件自己的高亮和复制菜单，不套用正文系统选区手柄；系统正文选区另用实际录屏说明。不要给手机叠加鼠标 hover。
- UI 动效沿用产品实录；光标移动、点击提示和取景推近属于后期讲解，可克制添加。支持选区工具栏的 Web 镜头可参考实现中的 140 ms 入场、100 ms 退场、约 700 ms 成功反馈停留；这些不是全部弹窗的统一参数，减少动态效果设置下也不强行动画化。
优先录制同一段真实内容的完整操作链，再剪辑。静态素材只能加标注和镜头运动；若制作手势路径示意，应持续标注“交互示意”，不能伪造操作后的界面状态。交互镜头与基准数据卡分开，不给演示录屏叠加测试计时器。

【新增交互的补充镜头库】
以下是已核对实现、前版分镜未完整介绍的交互。每个镜头给出具体操作，不以素材表中列过截图视为已经介绍。58 秒主片按下方覆盖表取舍；补充镜头只能替换等长镜头；所有版本均须少于 60 秒，不另行扩展片长。优先级依次为悬停与滚动、浮窗、行号与局部选区、表格菜单，其余按素材质量取舍。
A. 表格复制菜单的展开与收起（建议 5–7 秒）
鼠标停到表格左上角复制图标，方形按钮横向展开为圆角菜单，文字淡入；在两个条目间移动，菜单保持展开，条目出现实际 hover 背景；点击复制显示成功勾选，移开后文字先淡出、容器再收窄。只有录制环境支持复制图片时才展示该入口。
另拍双击单元格后的“复制选中”菜单：选区出现时菜单展开，复制成功后收起；触屏使用同一单元格连续点按两次，不画成鼠标双击。退场过程中再次选择可中断退场并重新展开，不闪回底层复制按钮。是否展示“添加到对话”以实际宿主能力为准。
实现参考：Web 普通表格菜单容器展开 180 ms、收起 160 ms，文字延后 40 ms 入场；选中单元格菜单同样有宽度与文字过渡，但不要把普通菜单的延迟参数套到它。仅作录制参考，减少动态效果时尊重实际表现。
旁白备选：“悬停展开复制菜单，双击选中整格；需要的内容，随手带走。”

B. 流式预览平滑跟随与阅读位置保持（建议 6–8 秒）
打开正在输出的 Shell 或思考预览，拍到标题运行标记和末尾随新内容平滑跟进；读者主动向上滚离末尾后，新输出继续增长，视口保留在阅读处；再回到底部，恢复跟随。不要把打开或调整大小时的定位也强行画成滑行动画。
旁白备选：“跟着新输出往下读；向上翻时，停在你正在看的位置。”

C. Markdown 代码预览的渲染／源码切换（建议 5–7 秒）
选择支持此预览的 Markdown、纯文本或未标语言代码块，点击真实预览按钮进入最大化窗口；用同一个切换按钮在渲染结果和原始文本之间切换，再在原始文本视图切换换行、复制源码。渲染视图的换行控件按实际禁用状态表现，不编造两个独立切换按钮或所有代码语言均可这样预览。
旁白备选：“打开预览，在渲染结果和原始文本之间切换。”

D. 实时待办浮窗与完成状态（建议 5–7 秒）
点击待办标题栏窗口按钮，将清单打开为独立浮窗；继续使用时间线，浮窗保持打开，并随真实任务状态更新；展示进度环到全部完成后的勾选圆圈。长任务名可点开换行。没有实际状态变化素材时，用标注示意，不伪造任务已经完成，也不额外添加代码中不存在的进度变形动画。
旁白备选：“把待办留在浮窗，继续工作，也能看见进度。”

E. 回复页脚 hover 提示、轮次详情与复制反馈（建议 6–8 秒）
悬停时间，显示带日期的完整本地时间及实际开始／结束时间标签；悬停耗时显示实际耗时提示。悬停模型名称打开轮次详情，鼠标移入详情里的复制按钮，面板保持可操作；复制模型、思考等级或时间等实际带复制入口的字段，拍到反馈。直接点击页脚模型名称复制的是原始模型名，显示名称与复制值不必相同，不伪造它们一致。
触屏长按回复页脚时展示居中的“轮次详情”，不表现为跳转到另一条回复，也不自动滚动时间线；当前已撤回轮次导航，不出现上一轮／下一轮按钮和编号标题。只展示已有模型、时间和用量字段，缺失 token 数据不补零；Grok、Cursor 当前隐藏不可靠耗时，不补造数值。
此处重点是提示与弹层的出现、停留和复制操作；居中详情当前没有入场动画，不额外配成产品自带的弹簧缩放。
旁白备选：“模型、时间和本轮用量，悬停查看；需要的信息，直接复制。”

【本轮允许引用的性能数据】
测量日期：2026-10-17。
Better Paseo：b9dfae6；宿主：Paseo 0.11.2。
Mac Studio：Apple M5 Max，18 核，64 GB，macOS 27.0.1。
Web 使用 production profiling 构建，Chrome 155，1280×900；最多四组隔离并行，实际重叠有变化。
以下对照均为“不开插件（Paseo 0.11.2）”与“Better Paseo”，每格取五次主组的中位数。
指标是“Web 整段回放的主线程 Task 时间”，单位秒，不是生成回复的等待时间、单帧耗时、帧率或整机 CPU 占用。

可用的两个例子：
- 代码块流式：不开插件 2.40 s → Better Paseo 1.27 s。
- 长回复：不开插件 4.77 s → Better Paseo 2.75 s。

整体描述：同轮 Web 十一个场景，对比不开插件，九项主线程 Task 时间更低、两项持平。
“持平”按协议定义：相差不到 10%，或双方整段 Task 时间均小于 0.5 秒。
这些是本轮观测中位数。Web 五十五对同版本 A/A 中有三十四对行渲染总量差异超过 10%；这是另一项指标的波动检查，不能说成 Task 时间的误差范围。
不要将这些观测写成稳定提速已经证实，也不要用条形图里的秒数模拟真实双屏竞速。

【必须保留的数据边界】
- 本轮共有 630 次计划内采样尝试：550 次回放、80 次长历史尝试。不能写成“630 项测试全部通过”。
- iOS 是 iPhone 16 Pro / iOS 18.6 开发版 Hermes 模拟器，不是真机或 Release 验收。
- 二十个 iOS 回放样本记录显示错误，涉及十七个配置组；当前版十一个回放场景中有六个不可比较。
- iOS 的 810 条／1 轮长历史当前版，有一次 simctl pbpaste 复制验证超时，三个阶段整组 N/A。不能从其余成功样本补算数字，也不能把超时定性为插件复制功能已确认故障。
- 不引用这些 N/A 组做 iOS 性能宣传。手机镜头展示功能，不承担性能证明。
- 不能宣称所有指标都优于原生：本轮 Web 行渲染总量的历史回放、默认工具日志更高；部分 CLS 和 JS 堆指标也更高。
- 工具测试保留各自默认展开状态，不能声称证明了强制展开工具正文的性能。
- JS 堆是强制 GC 后的 Web 读数，不是整个应用内存；不使用“全面省内存”“零卡顿”“全平台更快”等措辞。
- 810 条是记录条数，不是 810 轮对话；832 条场景才是 12 个实际 provider turn。不要把这些合成输入描述成真实用户会话。

【锁定分镜与旁白｜58 秒】
下列时间包含片头、转场与片尾。以一段可辨的开发会话贯穿前六段，剪辑连接连续动作，避免每段重置到产品全景。每段只完成列出的动作，不追加镜头库中的整套流程。

0–3 秒｜直接进入产品
画面：真实工具调用折叠为清楚的一行；产品名轻量出现，不放独立空白 logo 片头。
旁白：“Better Paseo，让对话更好读。”
屏幕文字：“Better Paseo · Paseo 插件”。

3–11 秒｜hover、弹窗与滚动
画面：悬停正在输出的 Shell 折叠行，保留默认 1 秒等待，预览出现；光标进入面板，短暂展示新输出平滑跟随，再向上滚动，视口停在正在阅读的位置。实际素材不能同时满足时优先保证悬停、打开和滚动完整，不补造输出变化。
旁白：“停一下，看细节。向上翻，留在你正在读的位置。”
屏幕文字：“悬停即预览”。

11–16 秒｜把阅读空间交给用户
画面：接续预览，拖动标题栏，再拖边缘扩大面板；动作结束停顿。主片不追加最大化、关闭的往返操作；最大化镜头可等长替换拖动镜头。
旁白：“拖动、拉大，按你的方式阅读。”
屏幕文字：“自由调整”。

16–23 秒｜行号拖选
画面：匹配切到已开启行号的 Read 预览，角标“已开启行号”；从一个行号拖到另一行号，高亮连续整行，复制后用小范围粘贴结果显示缩进与换行，不含显示行号。
旁白：“拖选几行，复制完整源码。”
屏幕文字：“整行选取 · 保留缩进”。

23–30 秒｜局部文本与输入框
画面：在支持选区浮条的 Web 工具正文拖选一句，浮条出现，点击 Add to chat；镜头跟到同一聊天的可见输入框，引用草稿出现，停顿确认结果。滚动收起浮条作为等长替换镜头，不在此段再加第二次选择。
旁白：“选中一句，带回输入框，继续问。”
屏幕文字：“选择 → 加入草稿”。
说明：没有可用输入框实录时改用 Copy 与实际成功反馈，不生成引用写入成功状态。

30–36 秒｜表格菜单的细节
画面：表格左上角按钮 hover 后横向展开，光标移到 Markdown 项并点击，展示成功勾选；移开后菜单收起。整格双击选择菜单可等长替换，二者不在六秒内连续演示。
旁白：“表格复制，也一样顺手。”
屏幕文字：“悬停展开 · 一键复制”。

36–43 秒｜触屏与主题
画面：手机或明确标注的模拟器真实录屏，长按折叠行打开预览，再滑动正文；用同构画面切换至深色。手机外框或离线 showcase 持续标“界面示意”，只能用标注说明手势，不能伪造交互结果。
旁白：“手机上，长按、滑动。浅色深色，都清楚。”
屏幕文字：“长按预览 · 滑动阅读”。不放移动端性能数字。

43–53 秒｜一张可读的实测卡
画面：仅展示一组统计，整张卡稳定停留，不穿插界面操作或模拟竞速。
标题：“代码块流式 · Web 主线程 Task 时间”。
主体两列：“不开插件 2.40 s” → “Better Paseo 1.27 s”。
说明第一行：“2026-10-17 · b9dfae6 · 每格 5 次中位数”。
说明第二行：“最多 4 组并行；存在波动，不代表稳定提速”。
来源提示：“完整条件、A/A 与 N/A：仓库 README”。
旁白：“本轮 Web 实测，主线程 Task 时间更低。采样存在波动，完整结果公开。”
以上指标、对照、单位和说明均须在手机观看尺寸下可读。完整设备与构建条件放在交付的数据说明页；主片不再追加第二组例子、十一场景汇总或 630 次采样卡，避免信息过载。
```
